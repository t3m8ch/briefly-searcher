# Хранить декодированные сообщения Telegram в JSONB

Для исторической выгрузки @brieflyru сохраняем в `raw_posts` полный декодированный объект сообщения в JSONB, не скачивая медиафайлы. Цель архива — читать сообщения и повторно выводить из них статьи при изменении правил склейки; JSONB удобен для такого анализа. Это представление схемы используемого клиента, а не исходные TL-байты Telegram: сериализацию и версию схемы нужно знать при чтении архива. Побайтовое сохранение TL-ответов отвергнуто как усложняющее захват и исследование данных; восстановить оригинальные байты из JSONB нельзя.

Решение действует для MTProto-источника. Основной источник части 1 — веб-лента `t.me/s`, для её строк `payload` — HTML блока ([ADR-0003](0003-web-preview-source.md)). Суть та же: храним исходник, а не извлечённые поля.
