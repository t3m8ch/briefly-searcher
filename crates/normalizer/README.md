# normalizer

`normalize(&[ParsedMessage]) -> Normalized` пересчитывает весь переданный
срез истории без БД, сети, разбора HTML и асинхронности. Входные ID уникальны;
порядок произвольный. Посты и статьи возвращаются по возрастанию ID.
Границу `newest_fetched_id` применяет вызывающий код, до вызова нормализатора.
Правила: [план](../../docs/normalizer-plan.md), раздел 2.

Обычные проверки: `just check`, `just test`, `just clippy`, `just fmt`.

Отдельный диагностический прогон по внешнему дампу pg_dump custom-format:

```sh
NORMALIZER_DUMP=/path/to/briefly_searcher.dump \
  heavy -- cargo test -p briefly-searcher-normalizer --release --test dump -- --ignored --nocapture
```

Если `pg_restore` отсутствует в PATH, задайте `PG_RESTORE=/path/to/pg_restore`.
Прогон читает только raw_posts через stdout pg_restore, не восстанавливает БД
и не записывает дамп в репозиторий. Печатает число блоков, постов, статей по
статусам, время разбора и общее время. Блоки, которые текущий парсер не смог
разобрать, выводятся отдельно как ошибки с ID и не включаются в статистику
статей. Это диагностика входа: рабочий процесс пересчёта должен считать такую
ошибку ошибкой всего пересчёта, как требует план.
